# Industrial Operations Platform

Backend for MES-style industrial operations: products, work centers and **production orders** with a
lifecycle state machine and production confirmations (good / scrap quantities). All data is simulated.

Built with **ASP.NET Core 10 Web API**, **Entity Framework Core 10** and **PostgreSQL 17**, following a
lightweight **Clean Architecture**.

> This is the first module of a larger portfolio project. Planned next steps: authentication (JWT),
> query optimization and pagination, API versioning/idempotency, messaging (RabbitMQ), caching (Redis),
> automated tests, CI/CD, Azure deployment, observability and an Angular frontend.

## Features

- REST API for products, work centers and production orders
- Production order lifecycle enforced by the domain model:
  `Planned → Released → InProgress → Completed`, and `Planned | Released → Cancelled`
- Production reports (confirmations) only while an order is `InProgress`
- Human-readable order numbers (`PO-000001`) generated by a PostgreSQL sequence
- Input validation with **FluentValidation**
- **Global exception handling** returning RFC 9457 **Problem Details** for every error
- **Optimistic concurrency** on production orders using PostgreSQL `xmin`
- EF Core **migrations**, including seed data
- OpenAPI document + **Scalar** interactive UI (development)

## Architecture

```
src/
├── IndustrialOps.Domain          Entities, business rules, domain exceptions. No dependencies.
├── IndustrialOps.Application     Use cases (services), DTOs, validators, repository interfaces.
├── IndustrialOps.Infrastructure  EF Core DbContext, mappings, migrations, repositories.
└── IndustrialOps.Api             Controllers, global exception handler, composition root.
```

Dependencies point inwards: `Api → Application → Domain` and `Infrastructure → Application → Domain`.
The Application layer defines interfaces (`IProductionOrderRepository`, `IUnitOfWork`) and the
Infrastructure layer implements them, so business code never depends on EF Core or PostgreSQL.

### Error responses

| Situation | Exception | HTTP |
|---|---|---|
| Invalid input / unknown referenced id | `ValidationException` | 400 |
| Resource in the URL not found | `NotFoundException` | 404 |
| Duplicated code / concurrent update | `ConflictException` | 409 |
| Business rule violated (e.g. invalid status transition) | `DomainException` | 422 |
| Anything else | — | 500 (no internal details exposed) |

```json
{
  "type": "https://tools.ietf.org/html/rfc4918#section-11.2",
  "title": "Business rule violation.",
  "status": 422,
  "detail": "Cannot start production order 'PO-000001' because it is Planned. Expected status: Released.",
  "instance": "POST /api/production-orders/0199.../start",
  "traceId": "00-d0ae9cf51253c56c4795008348ee711b-5d74141e38dead9c-00"
}
```

## Endpoints

| Method | Route | Description |
|---|---|---|
| GET / POST | `/api/products` | List (`?includeInactive=true`) / create |
| GET / PUT / DELETE | `/api/products/{id}` | Get / update / deactivate (soft delete) |
| GET / POST | `/api/work-centers` | List / create |
| GET / PUT / DELETE | `/api/work-centers/{id}` | Get / update / deactivate |
| GET / POST | `/api/production-orders` | List (`?status=InProgress`) / create |
| GET / PUT | `/api/production-orders/{id}` | Get / update planning (only while `Planned`) |
| POST | `/api/production-orders/{id}/release` | `Planned → Released` |
| POST | `/api/production-orders/{id}/start` | `Released → InProgress` |
| POST | `/api/production-orders/{id}/complete` | `InProgress → Completed` |
| POST | `/api/production-orders/{id}/cancel` | `Planned/Released → Cancelled` |
| GET / POST | `/api/production-orders/{id}/reports` | List / create production reports |

## Running locally

**Requirements:** .NET 10 SDK and PostgreSQL 17 (native install or Docker).

1. Start PostgreSQL
   - Docker: `docker compose up -d`
   - Native install: create the role and database:
     ```sql
     CREATE ROLE industrialops WITH LOGIN PASSWORD 'industrialops_dev';
     CREATE DATABASE industrialops OWNER industrialops;
     ```
   The development connection string (port `5433`) is in `src/IndustrialOps.Api/appsettings.Development.json`.
   These are local development credentials only; real environments must provide the connection string
   through environment variables or a secret store.

2. Run the API (migrations are applied automatically in development):
   ```bash
   dotnet run --project src/IndustrialOps.Api
   ```

3. Open **http://localhost:5080/scalar** to explore and call the API, or use
   `src/IndustrialOps.Api/IndustrialOps.http`.

### Migrations

```bash
dotnet tool install --global dotnet-ef

# create a migration
dotnet ef migrations add <Name> --project src/IndustrialOps.Infrastructure --startup-project src/IndustrialOps.Api --output-dir Persistence/Migrations

# apply migrations
dotnet ef database update --project src/IndustrialOps.Infrastructure --startup-project src/IndustrialOps.Api
```
